# 双平台独立运行与资料互通

状态：共享 core、CLI 与 Workbench 已接入 Windows/macOS 平台实现。macOS 已执行本机锁、控制通道、服务、安装与窗口验证；未在 Mac 上把跳过的 Windows API 用例计为通过。真实跨机器资料往返仍需两台机器验证。安装入口见 [INSTALL.md](../INSTALL.md)。

## 运行模型

Windows 和 macOS 分别运行完整的本地 CLI 与 Workbench，各自拥有本机工作区、配置和安装环境。两台机器可以互不在线，不要求发现、连接或通信，也没有中心服务、多端同步或跨机器并发写入目标。

Workbench 浏览器连接本机回环地址；启动器与本机服务交换认证和控制信息属于同机进程间通信。将这部分平台实现隔离，是为了在各操作系统保持同样的启动、认证、停止语义，并不增加机器之间的通信能力。

## 共享规则与平台实现

Project/Task/Run 的身份、字段、状态检查、阅读入口与导入校验由共享 core 维护。实现把真正变化的平台能力集中在少量内部接口，调用方只传结构化目标，不拼装 shell 命令。不提前引入插件框架或多存储后端。

| 能力 | 当前 Windows 实现 | macOS 实现 |
|---|---|---|
| 工作区写入互斥 | locking.WindowsMutex | flock 文件锁，同用户本机互斥；进程退出自动释放，锁文件不删除 |
| 进程与实例身份 | PID、创建时间、用户 SID | Darwin libproc 读取 PID、启动时间、有效 UID；保留记录字段 user_sid 并使用 uid: 前缀 |
| 本机认证与控制 | 当前用户受限命名管道 | 0700 私有目录中的 Unix socket；LOCAL_PEERPID 核对对端，令牌只经认证通道 |
| 应用打开 | WindowsOpener | MacOpener 通过 Launch Services 打开 Finder/默认浏览器/编辑器，参数数组不经过 shell |
| 安装与入口 | runtime 内 venv 和 cmd | bin/python、固定 shell 入口和独立 DUMMYSYS.app；应用写入使用登记 CLI 发行 |
| 路径与文件操作 | Windows 路径、原子替换、链接检查 | 解析平台路径，限制越界与链接穿越，保持原子写入/失败保留语义 |

共用层通过 `ports.Opener` 的小型协议使用平台能力，不引入庞大的平台抽象基类。`platform_runtime` 选择身份、锁、IPC 和应用打开实现；`native_host` 选择 WebView2/Cocoa 窗口后端。Windows 的 Edge profile 留在 Windows 浏览器适配器中。平台模块只接受结构化目标，Project/Task/Run 的状态机仍只有 core 中的一份。

macOS 原生窗口关闭时隐藏，重复 launch 经私有窗口控制通道恢复；⌘Q 停止服务再退出。服务正常停止或被替换后，旧窗口退出。Cocoa/Windows GUI 行为需独立实测，通用 HTTP 测试无法替代。

## 资料与本机状态

资料互通采用显式导出包和导入动作；用户可自行复制介质，不要求 DUMMYSYS 传输文件。

| 内容 | 导入目标 |
|---|---|
| 选定的知识正文、项目/Task 文档与引用附件 | 随资料迁移，校验引用和内容哈希 |
| Project/Task/Run 的逻辑 ID、编号、状态及历史来源 | 保留身份和语义，不因换机器重建 ID |
| 选定的 Run 原始结果与证据 | 随声明的范围迁移；未包含的资源明确标记，不把缺失证据记为完整 |
| Repo 逻辑关联 | 保留 repo_id 与相对范围，目标机重新绑定 checkout |
| 工作区绝对路径、应用路径、服务器连接凭据 | 不作为可用绑定直接导入；目标机显式配置，凭据不进入通用资料包 |
| Python 环境、可执行文件、浏览器用户数据、锁、进程/会话状态、缓存 | 不随资料迁移，在目标机重新生成 |
| Operation 写入/恢复日志 | 属于原机器操作现场，不在目标机重放；需保留时只作历史证据 |

runtime 同时容纳持久证据与可重建状态，不能把整个 runtime 都忽略，也不能整体复制。原始证据中的历史机器信息保留其来源含义，不伪装成目标机当前配置。

## 资料互通的共同约束

1. 导出前确认所选范围没有进行中的写入或待恢复 Operation，生成一致的资料清单。运行中的工作必须明确停止或作为不完整快照处理，不伪造完成状态。
2. 导出包声明独立的数据格式版本、对象身份、包内相对路径、文件哈希与未打包的外部引用；数据格式版本与产品发行版本分别表达。只接受明确支持的格式，未知版本保留原包并拒绝导入，不承诺自动跨版本升级。
3. 首次实现优先导入新工作区。新工作区生成自己的本机实例身份，Project/Task/Run ID 随资料保留；导入到已有工作区时遇到 ID 冲突拒绝覆盖，不默认合并或重复创建。
4. 不在导入时执行包内代码。验证目录穿越、绝对路径、符号链接/目录联接和解包大小；检查 Windows 保留名称、长度、大小写碰撞与 Unicode 名称差异。无法无损表示的路径明确拒绝并给出映射清单，不静默改名。
5. 当前文件中的工作区绝对引用通过已声明的来源根和相对路径映射到目标；不得对正文任意字符串作全局替换。稳定引用保持，外部 Repo/应用位置要求重新绑定；无法解析的引用列入报告。
6. 先在目标 runtime 暂存、校验，再经 core 受管操作生效。失败保留原包、暂存清单与恢复信息，不覆盖已有资料、不删除整个目标目录。
7. 导入后重建目录投影与阅读入口，核对 ID、文件哈希、引用和证据完整性。只有相应检查通过，才报告该次导入成功。

## 验证边界

Windows 已有 project export/import；共享资料校验和 Mac 文件锁下的导入导出回归在 Mac 执行。Windows → macOS → Windows 的真实双机往返、Obsidian 应用中的链接更新、Intel Mac 和其它 Python 版本仍需专门实测。先用构造资料，确认身份、引用与证据，再迁移真实资料。多端自动同步、远程控制、跨机器通信和同时写入不在范围内。
